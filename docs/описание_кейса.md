# МТС Energytool:

## ИИ-консультант для сайта


Аннотация

```
Бизнесу нужно снизить расходы на электроэнергию, наладить учет
и найти потери, но самостоятельно разобраться в сложных
энергетических продуктах получается не у всех. Создайте ИИ-
консультанта для сайта МТС Energytool: он должен понять задачу
клиента, задать уточняющие вопросы, подобрать подходящее решение,
объяснить его простым языком и передать менеджеру заявку с резюме
диалога.
```

ПОСТАНОВКА ЗАДАЧИ

```
Создайте ИИ-консультанта для сайта МТС Energytool, который ведет клиента от описания проблемы
до заявки менеджеру. Для этого:
```
1. Изучите базу знаний Energytool.
2. Реализуйте поиск по базе знаний (RAG). Бот должен находить релевантную информацию в базе знаний и использовать
    ее для подготовки ответа с учетом ситуации клиента.
3. Научите бота вести себя как консультант, а не как поисковик:
    выяснять, какую задачу решает человек, и подбирать подходящие продукты Energytool простым языком;
    задавать уточняющий вопрос, если запрос неясен или найденной информации недостаточно;
    говорить, что вопрос вне его компетенции, и предлагать связаться со специалистом.
4. Реализуйте сбор заявки. В подходящий момент диалога бот предлагает связаться с менеджером, собирает ФИО, телефон
    и название компании и формирует краткое резюме диалога.
5. Сохраняйте контекст в рамках одного диалога. Пользователь может переходить между темами и возвращаться к ним,
    а кнопка «Новый диалог» полностью сбрасывает контекст. Сохраняйте историю всех диалоговых сессий, включая разговоры
    без заявки.
6. Оптимизируйте скорость. Обеспечьте быстрые и стабильные ответы бота.
7. Создайте веб-интерфейс чата с режимом отладки, в котором видно время ответа и документы базы знаний, которые
    бот использовал.
8. Продумайте, как ИИ-консультанта можно встроить в сайт Energytool и передавать сформированные заявки менеджерам.


ФОРМАТ СДАЧИ

Решение сдается в два этапа. Во время хакатона участники отправляют сабмиты бота на автоматическую оценку ответов, в конце

сдают финальную версию проекта.

Этап 1 Сабмиты на автоматическую оценку

```
На платформу загружается ZIP-архив со скриптом solution.py —
единой точкой входа бота.
```
```
Платформа запускает скрипт на сервере в Docker-контейнере
и прогоняет через него тестовые вопросы. Каждый тест-кейс
обрабатывается независимо: на вход поступает одиночный во-
прос либо история короткого диалога. В диалоговом тесте
бот отвечает на последнюю реплику пользователя с учетом пе-
реданной истории. Состояние между тест-кейсами
не сохраняется. Затем LLM-судья оценивает сгенерированные
ответы, сравнивая их с эталоном и ответами бейзлайна. Ре-
зультат попадает в лидерборд.
```
```
Для генерации ответов
при автоматической проверке
используется единая языковая модель,
подключаемая через API организаторов.
Участники самостоятельно реализуют
поиск по базе знаний и логику
консультанта.
```
```
Подробные требования к формату сабмита,
запуску решения на платформе, доступным
моделям, техническим ограничениям
и порядку автоматической оценки приве-
дены в Техническом регламенте.
```

ОГРАНИЧЕНИЯ

1. Предоставленные для кейса данные можно
    использовать только для выполнения задания.
    Не публикуйте исходные выгрузки и их копии
    в открытых репозиториях или общедоступных
    хранилищах и не передавайте их третьим лицам.
2. Факты о продуктах Energytool, тарифах, технических
    характеристиках, ценах и условиях услуг бот берет только
    из предоставленной базы знаний. Сведения о ситуации
    клиента бот получает из диалога. Использовать
    неподтвержденные знания модели об энергетике нельзя.
3. Если ответа в базе знаний нет, бот прямо говорит об этом
    и предлагает связаться со специалистом. Придумывать
    ответ нельзя.
4. Бот консультирует только по продуктам Energytool
    и связанным с ними задачам клиента. Вопросы
    по технической документации, настройке систем учета
    и приборов в задачу не входят.
       5. Ответы бота должны быть краткими и понятными,
          как правило, не более 150 слов. Если вопрос требует
          подробного объяснения, допускается более длинный
          ответ. Ограничение не распространяется на резюме
          заявки для менеджера.
       6. После закрытия чата или нажатия «Новый диалог»
          бот начинает с чистого листа и не использует контекст
          предыдущих сессий. При этом история всех сессий, в том
          числе без заявки, сохраняется и доступна для проверки
          в прототипе.
       7. Реальные интеграции с CRM, сайтом или почтой
          не требуются. Заявка формируется внутри решения.
       8. Во время хакатона используйте только тестовые
          или выдуманные персональные данные.
       9. Нельзя размещать в репозитории API-ключи и другие
          секреты.
